## 🚀 Подготовка

### Требования
- ✅ Аккаунт на GitHub (если проект еще не в репозитории)
- ✅ Проект должен быть загружен в GitHub репозиторий
- ✅ Структура проекта должна содержать папку `server/` с файлами:
  - `server.js`
  - `package.json`
  - `railway.json` (уже создан)

### Проверка структуры проекта

Убедитесь, что в корне вашего репозитория есть следующая структура:

```
your-repo/
├── server/
│   ├── server.js
│   ├── package.json
│   ├── railway.json
│   └── .railwayignore
└── react-echarts-app/
    └── ...
```

## 🔐 Регистрация и настройка аккаунта

### Шаг 1: Регистрация на Railway

1. Перейдите на сайт [railway.app](https://railway.app/)
2. Нажмите кнопку **"Start a New Project"** или **"Login"**
3. Выберите способ регистрации:
   - **GitHub** (рекомендуется) - самый простой способ
   - Email
   - Google

### Шаг 2: Авторизация через GitHub (рекомендуется)

1. Нажмите **"Login with GitHub"**
2. Вас перенаправит на страницу авторизации GitHub
3. Нажмите **"Authorize Railway"** для предоставления доступа
4. Railway получит доступ к вашим репозиториям (можно ограничить доступ только к выбранным репозиториям)

### Шаг 3: Настройка бесплатного плана

1. После регистрации Railway автоматически предоставит бесплатный план
2. На бесплатном плане доступно:
   - $5 кредитов в месяц
   - Неограниченное количество проектов
   - Автоматические деплои из GitHub

## 🏗️ Создание проекта на Railway

### Шаг 1: Создание нового проекта

1. В Dashboard Railway нажмите кнопку **"+ New Project"** (вверху справа)
2. Появится меню с вариантами:
   - **Deploy from GitHub repo** (выберите этот вариант)
   - Empty Project
   - Deploy a Template

### Шаг 2: Выбор репозитория

1. Нажмите **"Deploy from GitHub repo"**
2. Если это первый раз, Railway попросит разрешение на доступ к репозиториям
3. Выберите ваш репозиторий из списка
4. Если репозиторий не виден:
   - Проверьте, что вы авторизованы через GitHub
   - Нажмите **"Configure GitHub App"** и выберите нужные репозитории
   - Обновите страницу

## 🔗 Подключение GitHub репозитория

### Шаг 1: Выбор репозитория

1. В списке репозиториев найдите ваш проект
2. Нажмите на него
3. Railway начнет процесс подключения

### Шаг 2: Настройка подключения

После выбора репозитория Railway может спросить:
- **Branch** - выберите ветку (обычно `main` или `master`)
- **Root Directory** - **ВАЖНО!** Укажите: `server`
  - Это критически важно, так как ваш сервер находится в папке `server/`
  - Если не указать, Railway будет искать `package.json` в корне репозитория

## ⚙️ Настройка деплоя

### Шаг 1: Автоматическое определение

Railway автоматически:
1. Определит, что это Node.js проект (по наличию `package.json`)
2. Прочитает `railway.json` для конфигурации
3. Установит зависимости через `npm install`
4. Запустит сервер через `npm start`

### Шаг 2: Проверка настроек

1. В Dashboard проекта нажмите на сервис (обычно называется как ваш репозиторий)
2. Перейдите во вкладку **"Settings"**
3. Проверьте следующие настройки:

#### Build & Deploy Settings:
- **Root Directory**: `server` (должно быть указано)
- **Build Command**: `npm install` (автоматически)
- **Start Command**: `npm start` (автоматически)

#### Environment:
- **NODE_ENV**: `production` (устанавливается автоматически)
- **PORT**: автоматически назначается Railway

### Шаг 3: Настройка вручную (если нужно)

Если автоматическое определение не сработало:

1. В Settings → **"Variables"** добавьте:
   ```
   NODE_ENV=production
   ```
2. В Settings → **"Build & Deploy"** укажите:
   - **Root Directory**: `server`
   - **Build Command**: `npm install`
   - **Start Command**: `npm start`

## ✅ Проверка деплоя

### Шаг 1: Мониторинг процесса деплоя

1. После подключения репозитория Railway начнет деплой
2. Перейдите во вкладку **"Deployments"** или **"Logs"**
3. Вы увидите процесс:
   ```
   Installing dependencies...
   Building...
   Starting...
   ```

### Шаг 2: Проверка логов

1. Во вкладке **"Logs"** вы должны увидеть:
   ```
   🚀 Server started in production mode
   📡 HTTP Server is running on port XXXX
   🔌 WebSocket Server is running on port XXXX
   🌐 Environment: production
   📦 Node version: vXX.XX.XX
   ```

2. Если видите ошибки:
   - Проверьте раздел [Устранение проблем](#устранение-проблем)

### Шаг 3: Проверка статуса

1. В Dashboard проекта статус должен быть **"Active"** (зеленый индикатор)
2. Если статус **"Failed"**:
   - Откройте логи и проверьте ошибки
   - Убедитесь, что Root Directory указан как `server`

## 🌐 Получение URL сервера

### Шаг 1: Генерация публичного URL

1. В Dashboard проекта нажмите на сервис
2. Перейдите во вкладку **"Settings"**
3. Прокрутите до раздела **"Networking"**
4. Нажмите **"Generate Domain"** или **"Add Custom Domain"**

### Шаг 2: Получение URL

Railway создаст URL вида:
```
https://your-project-name-production.up.railway.app
```

Или если вы указали кастомное имя:
```
https://your-custom-name.railway.app
```

### Шаг 3: Проверка доступности

1. Откройте браузер
2. Перейдите по URL: `https://your-url.railway.app`
3. Должен вернуться JSON:
   ```json
   {
     "message": "Hello from Node.js server!",
     "environment": "production",
     "timestamp": "..."
   }
   ```

4. Проверьте health endpoint: `https://your-url.railway.app/api/health`
5. Должен вернуться JSON с информацией о сервере

### Шаг 4: WebSocket URL

Для WebSocket используйте тот же домен, но с протоколом `wss://`:
```
wss://your-url.railway.app
```

**Важно**: Используйте `wss://` (безопасное соединение), а не `ws://`

## 🔧 Настройка переменных окружения

### Автоматические переменные

Railway автоматически устанавливает:
- `PORT` - порт сервера (не нужно устанавливать вручную)
- `NODE_ENV=production` - окружение

### Дополнительные переменные (если нужны)

Если в будущем понадобятся дополнительные переменные:

1. В Dashboard проекта → **Settings** → **Variables**
2. Нажмите **"+ New Variable"**
3. Укажите:
   - **Name**: имя переменной
   - **Value**: значение
4. Нажмите **"Add"**
5. Railway автоматически перезапустит сервис

## 🔄 Обновление клиента

### Шаг 1: Получение URL сервера

Скопируйте URL вашего Railway сервера:
- HTTP: `https://your-url.railway.app`
- WebSocket: `wss://your-url.railway.app`

### Шаг 2: Обновление конфигурации клиента

В вашем React приложении (`react-echarts-app`) нужно обновить URL:

1. Создайте файл `.env.production` в папке `react-echarts-app/`:
   ```env
   VITE_WS_URL=wss://your-url.railway.app
   VITE_API_URL=https://your-url.railway.app
   ```

2. Обновите код для использования переменных окружения вместо `localhost:3000`

### Шаг 3: Деплой клиента на Netlify

После обновления конфигурации задеплойте клиент на Netlify с новыми переменными окружения.

## 🐛 Устранение проблем

### Проблема 1: "Could not determine how to build the app"

**Причина**: Railway не может найти `package.json`

**Решение**:
1. Убедитесь, что в Settings указан **Root Directory**: `server`
2. Проверьте, что файл `server/package.json` существует
3. Перезапустите деплой

### Проблема 2: "Port already in use"

**Причина**: Конфликт портов (редко на Railway)

**Решение**:
1. Railway автоматически назначает порт через переменную `PORT`
2. Убедитесь, что в `server.js` используется `process.env.PORT`
3. Перезапустите сервис

### Проблема 3: "Module not found"

**Причина**: Зависимости не установлены

**Решение**:
1. Проверьте, что `package.json` содержит все зависимости
2. Убедитесь, что Root Directory указан правильно
3. Проверьте логи сборки - должны быть строки `npm install`

### Проблема 4: WebSocket не подключается

**Причина**: Неправильный протокол или URL

**Решение**:
1. Используйте `wss://` вместо `ws://` для безопасного соединения
2. Убедитесь, что используете правильный домен Railway
3. Проверьте, что сервер запущен (статус Active в Dashboard)

### Проблема 5: CORS ошибки

**Причина**: Сервер блокирует запросы с другого домена

**Решение**:
1. В `server.js` уже настроен CORS с `Access-Control-Allow-Origin: *`
2. Если проблема сохраняется, проверьте логи сервера
3. Убедитесь, что клиент использует правильный URL

### Проблема 6: Сервис не запускается

**Решение**:
1. Откройте вкладку **"Logs"** в Dashboard
2. Проверьте последние строки логов на наличие ошибок
3. Убедитесь, что:
   - Node.js версия совместима (>=18.0.0)
   - Все зависимости установлены
   - `package.json` содержит правильный `start` скрипт

### Проблема 7: Деплой зависает

**Решение**:
1. Отмените текущий деплой
2. Проверьте логи на наличие ошибок
3. Убедитесь, что Root Directory указан правильно
4. Попробуйте перезапустить деплой вручную
